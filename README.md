# 🗺️ GeoGuessr СПб — «Петербургский следопыт»

Локальный аналог игры GeoGuessr для Санкт-Петербурга. Вас «высаживают» в случайную
точку города — нужно осмотреться в панораме улиц и угадать на карте, где это.

## 🎮 Как играть

1. Игра выбирает случайную точку в Петербурге и показывает **панораму улиц** Яндекса в этом месте.
2. Осмотритесь и отметьте на карте, где, по вашему мнению, вы находитесь.
3. Чем ближе к реальной точке — тем больше очков (максимум **5000** за раунд).
4. Игра состоит из **5 раундов**, максимальный счёт — **25000**.

### Уровни сложности

Точки генерируются вокруг центра города с разным разбросом:

| Режим | Разброс | Описание |
|-------|---------|----------|
| 🏛️ Центр | ~1.5 км | Исторический центр |
| 🏙️ Средняя | ~3 км | Центр и ближайшие районы |
| 🌆 Весь город | ~6–12 км | От центра до окраин |

Дополнительно есть режим **🚷 «не сходя с места»**: осматриваться можно,
ходить по стрелкам — нельзя (шаг откатывается). Такие игры помечаются
бейджем в таблице лидеров.

Режимы не сравнимы напрямую (в «Центре» угадывать проще), поэтому в таблице
лидеров у каждой записи показан её режим, а саму таблицу можно отфильтровать
по сложности.

### ⏱ Таймер раунда

На старте можно ограничить время на раунд (1 или 3 минуты). Когда время
выходит, ответ отправляется автоматически; если точка не отмечена — раунд
приносит 0 очков. Лимит проверяется и на сервере: опоздавший ответ не
засчитывается. Отсчёт начинается только после появления панорамы, поэтому
медленная сеть не съедает игровое время. Игры с таймером помечены в таблице
лидеров бейджем ⏱.

### ⚔️ Челлендж-ссылки

После завершения игры кнопка «Бросить вызов другу» копирует ссылку вида
`/?challenge=TOKEN`. Открывший её игрок сыграет **те же самые 5 точек** с теми
же настройками, а в конце увидит сравнение своего счёта со счётом автора.

### 🗓 Вызов дня

Один общий набор из 5 точек на день (день — по петербургскому времени) для
всех игроков и отдельный топ «сегодня». Одна попытка в день; недоигранный
вызов можно продолжить. Кнопка на стартовом экране показывает, сколько
человек уже сыграло сегодня.

### 🧠 Пул проверенных точек

Каждая сыгранная панорама сохраняется в пул проверенных точек. Когда в пуле
накопилось хотя бы 15 подходящих мест, в обычной игре вероятность взять одно
из них — **70%**, а оставшиеся **30%** раундов исследуют новые случайные места.
Эта доля не уменьшается по мере дальнейшего роста пула.
Если у новой точки съёмки действительно нет, после одной проверки игра быстро
восстанавливает раунд точкой из пула; сетевой сбой повторяет ту же точку и не
помечает её плохой. Вызов дня при достаточном пуле состоит только из уже
проверенных мест, чтобы общий для всех набор не менялся из-за пропуска.

Пул поддерживает себя сам: если панорама у точки перестала находиться
несколько раз подряд (Яндекс иногда убирает съёмку) — точка выбывает.
А владелец может модерировать пул руками на странице `/admin` (карта всех
точек, ссылка на панораму, удаление «некрасивых» мест) — доступ по
`ADMIN_KEY` из окружения.

### 📊 Сложность мест — из данных

По накопленным парам «догадка → ответ» считается фактическая сложность
каждой точки пула (средний промах игроков) — на экране результата
показывается «это место сложнее N% точек города».

### 📱 PWA

Сайт устанавливается на телефон как приложение (манифест + иконки).
На мобильных карта — сворачиваемый «нижний лист»: панораму можно смотреть
на весь экран, не сбрасывая позицию. Пока игрок смотрит результат, приложение
один раз ищет панораму следующего раунда и прогревает несколько её самых
лёгких тайлов. Скрытый панорамный Player для этого не создаётся, поэтому
предзагрузка не расходует второй WebGL-контекст и заметно меньше нагружает
телефон.

## 🚀 Быстрый старт

### 1. Установка зависимостей

```bash
cd geoguessr-spb
python3 -m venv venv
source venv/bin/activate  # На Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Настройка переменных окружения

```bash
cp .env.example .env
```

Отредактируйте `.env`:
- `SECRET_KEY` — секретный ключ Flask (`python3 -c "import secrets; print(secrets.token_hex(32))"`)
- `YANDEX_MAPS_API_KEY` — API-ключ Яндекс.Карт ([developer.tech.yandex.ru](https://developer.tech.yandex.ru/))
- `SESSION_COOKIE_SECURE` — `false` для локальной разработки по http (иначе cookie сессии не сохранится)
- `ADMIN_KEY` — *(необязательно)* ключ страницы модерации пула `/admin` (там же — сводка: игры, доигрываемость)
- `METRIKA_ID` — *(необязательно)* счётчик Яндекс Метрики с целями game_start/game_complete/daily_start/challenge_accept/challenge_share
- `FLASK_DEBUG` — `true` только для локальной отладки
- `DATABASE_URL` — *(необязательно)* URI базы; по умолчанию SQLite-файл в `instance/`

### 3. Запуск приложения

```bash
python app.py
```

Откройте в браузере: [http://localhost:5000](http://localhost:5000)

> Схема БД создаётся и обновляется автоматически при старте (Alembic-миграции
> через Flask-Migrate). Базы, созданные старыми версиями приложения,
> подхватываются и мигрируются без потери данных.

### 🐳 Docker

```bash
cp .env.example .env   # заполнить ключи
docker compose up --build
```

Приложение поднимется на [http://localhost:8000](http://localhost:8000) под
gunicorn; база SQLite хранится на хосте в `./instance/`.

### Production: Apache → Gunicorn

Продовая схема не запускает Flask через `mod_wsgi`: Apache завершает TLS и
проксирует запросы в Gunicorn на `127.0.0.1:8000`. Готовый vhost хранится в
[`deploy/apache/geoguessr.conf`](deploy/apache/geoguessr.conf), поэтому конфиг
можно одинаково развернуть на другом Ubuntu-сервере.

Необходимые модули Apache: `proxy`, `proxy_http`, `ssl`, `headers`, `rewrite`
и `http2`. Сертификат Certbot должен использовать Apache как authenticator и
installer; после настройки это проверяется командой `certbot renew --dry-run`.

Файлы `geoguessr-staging.conf.example` и `ports-staging.conf.example` позволяют
сначала проверить проксирование на `127.0.0.1:8081`, пока текущий frontend всё
ещё занимает порты 80/443.

## 🗃️ Миграции БД

Схема управляется Flask-Migrate (Alembic). По умолчанию миграции применяются
автоматически при старте приложения (`AUTO_MIGRATE=true`). Для ручного
управления:

```bash
export FLASK_APP=app.py
flask db upgrade            # применить миграции
flask db migrate -m "..."   # сгенерировать новую после правки models.py
```

При multi-worker запуске gunicorn без `--preload` отключите автомиграции
(`AUTO_MIGRATE=false`) и применяйте их отдельным шагом деплоя.

## 🧪 Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты используют отдельную временную БД (через `DATABASE_URL`) и не трогают
рабочую базу. Покрыты: расчёт расстояния и очков, валидация координат,
генерация точек, идемпотентные повторы запросов, полный проход игры, пул
проверенных точек, таймер, челленджи, вызов дня, статистика сложности, режимы
и лимиты.

E2E-тесты (`tests/e2e/`) гоняют полный игровой цикл в реальном Chromium
через Playwright с управляемой заглушкой Яндекс.Карт — без сети и ключей. В
том числе проверяются медленный prefetch, отсутствие двойного Player,
пропавшее покрытие, временный сетевой сбой и быстро закрытый модальный Player:

```bash
python -m playwright install chromium   # один раз
pytest tests/e2e/
```

Всё вместе автоматически запускается в GitHub Actions на каждый push.

## ⚙️ Технологии

- **Backend**: Python 3, Flask, SQLAlchemy, Flask-Migrate (Alembic), Flask-Limiter, Gunicorn (прод за nginx)
- **Frontend**: HTML5, CSS3, JavaScript (ES6+)
- **Карты**: Яндекс.Карты JS API v3 (карта выбора/результата) + v2 (панорамы и асинхронный адрес)
- **База данных**: SQLite (через `DATABASE_URL` можно заменить на PostgreSQL и т.п.)

Для SQLite приложение включает WAL, `busy_timeout` и проверку соединений: это
снижает число редких ошибок блокировки при работе нескольких gunicorn worker'ов.

| POST | `/api/game/start` | Начать игру; первая локация уже находится в ответе |

| POST | `/api/game/ready` | Зафиксировать появление панорамы и получить дедлайн таймера |
| POST | `/api/game/skip_location` | Сменить точку; `location_version` делает сетевой повтор идемпотентным |
| POST | `/api/game/set_actual_point` | Совместимый endpoint для старых клиентов |
| POST | `/api/game/guess` | Идемпотентно отправить догадку с `round_id`; возвращает следующую локацию |
| POST | `/api/game/set_address` | Best-effort сохранить асинхронно найденный адрес |
| POST | `/api/game/panorama_metric` | Записать время поиска/появления и статус панорамы |
| GET | `/api/game/results` | Результаты игры: раунды с координатами, сравнение челленджа |
| GET | `/api/challenge/<token>` | Информация о челлендже для приглашённого игрока |
| GET | `/api/player/stats?name=` | Статистика игрока: игр, лучший и средний счёт |
| GET | `/api/daily` | Инфо о вызове дня (сыграл ли, сколько игроков сегодня) |
| GET | `/api/daily/leaderboard` | Топ сегодняшнего вызова дня |
| GET | `/api/leaderboard` | Таблица лидеров (`?difficulty=…`, `?period=week\|month\|all`) |
| GET/DELETE | `/api/admin/points[/<id>]` | Модерация пула точек (заголовок `X-Admin-Key`) |

## 🛡️ Защита от накрутки

- **Состояние игры хранится на сервере.** В cookie клиента — только id игры;
  номер активного раунда и начисленные очки нельзя откатить реплеем старой
  cookie. Каждый изменяющий запрос привязан к `round_id`, поэтому поздний ответ
  старого раунда не портит следующий.
- **Панорама проверяется по расстоянию.** Реальные координаты панорамы присылает
  клиент, поэтому сервер принимает их, только если они не дальше 1 км от
  сгенерированной им точки. Иначе очки считаются по серверной точке.
- **Серверные лимиты.** Перегенерация точки — не больше 10 раз на раунд
  (нельзя рероллить до знакомого места); создание игр и чтение лидерборда
  ограничены по частоте (Flask-Limiter).
- **Таймер проверяется на сервере.** В игре с лимитом времени опоздавший ответ
  получает 0 очков независимо от поведения клиента.

Это защита от случайных повторов и простой накрутки, а не строгий
соревновательный anti-cheat: браузер неизбежно получает координату, возле
которой должен открыть панораму.
